## 📖 1. نبذة عن المشروع (About the Project)

هذا المشروع هو **منظومة سحابية وإلكترونية متكاملة وشاملة** مخصصة لإدارة ومتابعة شؤون وأنشطة **أسرة الأنبا أرسانيوس والقديس نيقولاوس لوسائل الإيضاح**. تم تصميم وبرمجة النظام ليعمل بكفاءة فائقة على كافة الأجهزة (الهواتف الذكية، الأجهزة اللوحية، الحواسيب المحمولة والمكتبية) مع واجهة مستخدم فائقة الجمالية والسرعة تجمع بين السهولة المطلقة في الاستخدام وأحدث المعايير البرمجية والأمنية العالمية.

المشروع جاهز تماماً للنشر والعرض المباشر، ولا يتطلب أي أوامر معقدة أو إعدادات برمجية للتشغيل.

## 💎 2. أبرز ميزات المنظومة (Key Features)

### 🎨 أولاً: تجربة مستخدم ملكية (Liquid Glass Design)
- **ألوان مستوحاة من الشعار الرسمي:** تناغم بصري دقيق مع درجات البني الملكي، الكهرماني، الذهبي، والعاجي، لإبراز أصالة وروحانية الخدمة.
- **تأثيرات الزجاج السائل:** شفافيات ومؤثرات زجاجية راقية (`backdrop-filter: blur`)، وحواف مضيئة وظلال ناعمة تفاعلية.
- **الجزء العلوي الذكي (Smart Auto-Hiding Header):**
  - يختفي الهيدر وأزرار التحكم بسلاسة تامة عند التمرير لأسفل (`Scroll Down`) لإتاحة مساحة العرض كاملة لبطاقات الأشخاص والمهام.
  - يعود للظهور الفوري والناعم بمجرد التمرير لأعلى (`Scroll Up`) أو الوصول لبداية الصفحة للوصول السريع للأدوات.
  - زر عائم دائري زجاجي (`Back to Top`) يظهر عند التمرير للصعود بنقرة واحدة.
- **دعم كامل للوضعين (النهاري والليلي):** تبديل سلس مع حفظ تفضيل المستخدم في التخزين المحلي.
- **دعم ثنائي اللغة (عربي / إنجليزي):** مع توجيه ديناميكي كامل للواجهة (`RTL` و `LTR`).

### 👥 ثانياً: إدارة ومتابعة الأفراد والخُدام والمخدومين
- **بطاقات تفاعلية أنيقة للأشخاص (`person-card`):**
  - عرض الاسم، الدور (خادم / مخدوم)، تاريخ الميلاد، رقم الهاتف، والملاحظات.
  - أزرار اتصال ومراسلة مباشرة عبر **واتساب (WhatsApp)** والمكالمات الهاتفية بضغطة زر.
- **محرك بحث فوري متقدم:**
  - فلترة وتصفية لحظية بالاسم أو رقم الهاتف بمجرد كتابة أول حرف.
  - عداد فوري للنتائج المطابقة وزر مسح سريع لحقل البحث.
- **سجل الحضور والغياب الذكي:**
  - تسجيل حالات الحضور المتعددة: حاضر، غائب، معتذر، تأخير.
  - حساب تلقائي وفوري لنسب الحضور ومؤشرات الالتزام مع رسوم بيانية توضيحية.
- **إضافة وتعديل وحذف الأشخاص:** بنوافذ منبثقة زجاجية عصرية والتحقق من صحة المدخلات.

### 📋 ثالثاً: إدارة المهام والأنشطة (Task Management)
- توزيع المهام على الخدام والمخدومين ومتابعة مراحل التنفيذ (قيد الانتظار، جاري العمل، مكتملة).
- تحديد تواريخ الاستحقاق ودرجات الأولوية (عالية، متوسطة، عادية).
- إحصائيات وإشعارات فورية بحالة إنجاز التكليفات.

### 📅 رابعاً: الفعاليات والاجتماعات والأنشطة (Events & Calendar)
- جدولة الاجتماعات الأسبوعية، القداسات، المعارض، وورش وسائل الإيضاح.
- تسجيل حضور الاجتماعات وربطه المباشر بملفات الأفراد.

### 📊 خامساً: التقارير والتحليلات والنسخ الاحتياطي
- لوحة مؤشرات قياسية تعرض إجمالي الأعضاء، نسب الحضور الأسبوعية والشهرية، ومعدلات النشاط.
- **تصدير واستيراد البيانات:** إمكانية تصدير البيانات إلى ملفات Excel/CSV والنسخ الاحتياطي بصيغة JSON لضمان سلامة البيانات دائماً.

## 🔒 3. معمارية الأمان والصلاحيات السحابية (Security & Access Control)

يعتمد النظام على بنية هجينة فائقة المرونة تضمن استمرارية العمل في كل الظروف:

```text
[المتصفح / العميل]
        │
        ├──► Firebase Firestore (المزامنة السحابية اللحظية Realtime)
        │       └─► قواعد الأمان (firestore.rules):
        │             ├─ قراءة عامة مفتوحة للجميع (Public Read for Preview & Transparency)
        │             └─ التعديل والإضافة مقيد للخدام والمسؤولين فقط (Servant & Admin Roles)
        │
        └──► الخادم المحلي (Express 5 Local API & JSON Fallback)
                └─► في حال عدم توفر الإنترنت أو انقطاع الاتصال بالسحابة
```

1. **المعاينة المفتوحة (Open Public Preview):**
   - تم ضبط قواعد السحابة (`firestore.rules`) لتسمح بالمشاهدة والقراءة لجميع المستخدمين بدون قيود (`allow read: if true;`) لتمكين أي شخص من معاينة الموقع مباشرة من أي رابط.
2. **حماية التعديل والإدخال:**
   - عمليات الإضافة، التعديل، والحذف محمية برمجياً وتتطلب تسجيل دخول بحساب خادم معتمد (`Servant`) أو مسؤول (`Admin`).
3. **التحمل والمقاومة (High Fault Tolerance):**
   - في حال كان اتصال Firestore جديداً أو فارغاً، يتم تحميل البيانات فورياً من قاعدة البيانات الاحتياطية المدمجة (`data.json`) عبر الـ API بدون أن تظهر شاشة بيضاء أو فارغة.

## 📂 4. شجرة وهيكل ملفات المشروع (Clean Code Structure)

تم تنظيم المشروع بنمط البنية الموحدة النظيفة، وتم استبعاد أي حزم أو ملفات غير مستخدمة (مثل نسخة فلاتر السابقة):

```text
/ (جذر المشروع)
│
├── index.html                   # الصفحة الرئيسية وواجهة المستخدم الكاملة (Liquid Glass UI)
├── app.js                       # عقل التطبيق: إدارة الأحداث، الحضور، البحث، والمزامنة السحابية
├── server.js                    # خادم Node.js / Express 5 الآمن لتقديم الموقع وواجهات الـ APIs
├── data.json                    # قاعدة البيانات المحلية المدمجة (بيانات الأعضاء والمهام)
├── logo.png                     # الشعار الرسمي المعتمد لأسرة الأنبا أرسانيوس والقديس نيقولاوس
│
├── firestore.rules              # قواعد الأمان السحابية لقاعدة بيانات Firestore
├── firebase-applet-config.json  # معرفات الاتصال بمشروع Firebase السحابي
├── firebase-blueprint.json      # المخطط الهيكلي لمجموعات وحقول قاعدة البيانات
│
├── package.json                 # الحزم البرمجية والسكربتات المعتمدة (Express, Firebase, etc.)
├── bun.lock                     # قفل التبعيات لضمان استقرار الإصدارات
├── metadata.json                # بيانات التطبيق وصلاحياته الرسمية في منصة التشغيل
├── .env.example                 # نموذج المتغيرات البيئية
├── run_local.bat                # سكربت تشغيل محلي بنقرة واحدة لنظام ويندوز (بدون CMD)
│
├── README.md                    # هذا الملف: دليل الاستخدام والتوثيق الشامل للمشروع
└── PROJECT_AUDIT_AR.md          # تقرير التدقيق الهندسي وسجل التحديثات
```

## 🛠️ 5. تفاصيل الملفات الأساسية (File Breakdown)

| اسم الملف | النوع | الوظيفة الأساسية |
| :--- | :--- | :--- |
| `index.html` | الواجهة (HTML5/CSS) | تحتوي على كافة المكونات البصرية: الهيدر الذكي، شريط البحث، شبكة البطاقات، النوافذ المنبثقة، ولوحات الإحصائيات مع استدعاء Tailwind CSS و FontAwesome و Google Fonts. |
| `app.js` | المحرك (Vanilla JS) | يحتوي على منطق الحسابات، التهيئة اللحظية لـ Firestore SDK v13، محرك البحث الفوري، آليات التبديل للغة والوضع الليلي، ومنظومة المعالجة الذاتية للبيانات. |
| `server.js` | الخادم (Express 5) | خادم سريع ومحمي يستمع للمنفذ `3000`، يوفر مسارات REST API لقراءة وتحديث البيانات محلياً مع دعم CORS وتأمين الترويسات. |
| `data.json` | قاعدة البيانات | ملف JSON متكامل يحتوي على سجلات الخدام، المخدومين، سجلات الغياب والأنشطة كنسخة احتياطية مستمرة. |

| `run_local.bat` | سكربت تشغيل | ملف تشغيل أوتوماتيكي لنظام Windows يقوم بتشغيل الخادم وفتح المتصفح تلقائياً بنقرة واحدة. |

## 🚀 6. طرق التشغيل والنشر (How to Run & Deploy)

### الخيار 1️⃣: المعاينة السحابية المباشرة (Cloud Preview - AI Studio)
- **لا تتطلب أي تدخل:** بمجرد فتح المشروع في البيئة السحابية، يبدأ الخادم المدمج تلقائياً على المنفذ `3000`.
- يمكنك مشاهدة الموقع فوراً في نافذة المعاينة المباشرة المقابلة واستعراض كافة الميزات.

### الخيار 2️⃣: التشغيل المحلي بنقرة واحدة على ويندوز (One-Click Local)
إذا قمت بتنزيل ملفات المشروع كملف مضغوط على جهاز الحاسوب:
1. تأكد من تثبيت [Node.js](https://nodejs.org/) على جهازك.
2. اضغط نقراً مزدوجاً على الملف **`run_local.bat`**.
3. سيقوم السكربت بالتحقق من الحزم وتشغيل الخادم تلقائياً وفتح الموقع في متصفحك الافتراضي على العنوان `http://localhost:3000`.

### الخيار 3️⃣: التشغيل عبر سطر الأوامر (Command Line)
```bash
# تثبيت التبعيات (يتم لمرة واحدة فقط)
npm install

# تشغيل خادم التطوير
npm run dev

# أو بدء الخادم المباشر
npm start
```
ثم افتح الرابط: `http://localhost:3000`

## 🔌 7. نقاط الاتصال البرمجية (API Endpoints)

يوفر خادم `server.js` واجهات برمجية خفيفة وسريعة:

- `GET /api/status`: فحص حالة الخادم وجاهزيته (Healthcheck).
- `GET /api/people`: جلب قائمة كافة الأشخاص والمخدومين والخدام.
- `POST /api/people`: إضافة شخص جديد للبيانات المحلية.
- `PUT /api/people/:id`: تحديث بيانات شخص محدد.
- `DELETE /api/people/:id`: حذف شخص من السجلات.
- `POST /api/attendance`: تسجيل وتحديث حالة حضور أسبوعية.
- `GET /api/tasks`: جلب سجل المهام والتكليفات.
- `POST /api/tasks`: إنشاء مهمة جديدة.
- `GET /api/export`: استخراج وتنزيل نسخة احتياطية لكافة بيانات النظام.
